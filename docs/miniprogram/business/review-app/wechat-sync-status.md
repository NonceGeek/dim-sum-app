## 本轮讨论结论：身份关联、同步时机与操作环境

### OpenID 和 UnionID 保存在哪里

服务号回调收到关注事件后，将服务号 OpenID 保存到生产数据库 `WechatServiceFollower.openId`，按 `(appId, openId)` 唯一识别关注者。即使该人尚未注册平台，也会独立保留记录。ECS 查询微信用户资料后，把 UnionID 保存到同一行的 `unionId`。

同步随后以该 UnionID 查找 `Account` 中 `provider=wechat` 且 `unionId` 相同的账号，唯一匹配且无冲突时，将服务号 OpenID 写入 `Account.openIdWxService`。这里存的是服务号 OpenID，不是小程序 OpenID；`provider=sms` 描述登录方式，不会把该字段的含义变成小程序身份。

`needsSync`、`subscribed` 均为 `WechatServiceFollower` 的实际数据库布尔字段：

| 字段/状态 | 含义 |
| --- | --- |
| `subscribed=true` | 系统记录该用户正在关注服务号 |
| `needsSync=true` | 需要查询微信资料并重试关联，进入小时增量队列 |
| `needsSync=false` | 资料已同步或当前无需排队；不等于平台账号已绑定成功 |
| 资料同步成功但未匹配 | 已保存关注状态和 UnionID，但平台没有相同 UnionID 的微信账号，仍会置 `needsSync=false` |

关注回调将记录设为已关注、待同步；取关回调实时记录取关、取消排队并清空对应微信账号的推送地址。重复/过期回调由事件时间等检查处理，不靠重复新建用户记录。

### 纯手机号用户与后续关联

仅用手机号注册和登录、未关联微信身份的用户，即使关注服务号，当前程序也不能从 UnionID 推断其手机号账号。用户资料接口不提供手机号用于这种匹配。必须先把微信身份关联到平台用户，不要求最初一定用微信注册。

当前仓库没有独立的“已登录手机账号 → 绑定微信”入口；已有的是“微信登录 → 个人资料绑定手机号 → 已有手机号账号时确认合并”。普通切换微信/短信登录不等于关联同一用户，可能进入两个不同账号。

后续触发规则以当前代码为准：

| 场景 | 再次尝试服务号关联的时机 |
| --- | --- |
| 小程序微信登录或首次微信注册 | 登录流程调用 `bindUnionId(unionid)`；需已有同 UnionID、仍关注且已完成资料同步的记录 |
| Web 微信登录/注册 | 当前没有同样的即时补绑定调用，由每日全量兜底 |
| 手机号绑定或普通账号合并 | 当前没有统一即时补绑定调用，可在之后小程序微信登录或每日全量时重试；本轮人工合并另行执行了定向验证 |
| 小时增量 | 只处理 `needsSync=true`，不会自动扫此前已同步但未匹配的记录 |
| 每日全量 | 扫描全部关注者，不受 `needsSync=false` 限制，重新尝试未匹配或冲突记录 |
