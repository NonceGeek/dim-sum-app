# 参赛前问卷业务规则

> 状态：单租户 V1 研发基线
> 业务与接口负责人：Fynn
> 更新时间：2026-08-20

## 1. 目标与边界

参赛前问卷是活动投稿链路的一部分，不是通用注册、用户画像编辑或营销资料收集功能。

问卷只在已登录用户于活动详情页主动点击“我要投稿”后触发。浏览首页、活动列表、活动详情、分享活动或返回小程序时均不得自动触发。

V1 负责：

- 收集固定版本的年龄区间、语言文化地区和兴趣类型。
- 确保用户已有经过短信验证的 `User.phoneNumber`。
- 将问卷档案与用户 UID 绑定并在后续活动中复用。
- 记录首次登记和资料复用两条旅程所需的服务端事件。
- 为后台聚合洞察提供稳定的数据源。

V1 不负责：

- 通用问卷搭建器或运营自定义题目。
- 用户查看、修改或删除问卷答案。
- 问卷答案版本历史。
- 手机号营销触达。
- 用户级问卷答案批量导出。
- 多租户运行时隔离；多租户仅保留实施计划。

## 2. 领域术语

### 2.1 活动标签

`activityTag` 是活动自身的运营维度：

- 来源：活动后台创建或编辑活动。
- V1 数量：一个活动一个标签。
- 格式：恰好四个字符。
- 示例：饮食文化、粤语表达、城市记忆、传统技艺。
- 存储：`corpus_collection_activities.tags[0]`。
- 看板用途：按活动标签聚合登记与投稿表现。

### 2.2 用户兴趣类型

`interestTypes` 是用户问卷答案：

- 来源：参赛前问卷第三题。
- 规则：选填、多选、去重，不接受自定义文本。
- 看板用途：用户兴趣画像；不得替代活动标签。

活动标签与兴趣类型必须使用不同字段、不同接口名称和不同图表标题。

## 3. 问卷 Schema V1

服务端是问卷选项与校验规则的唯一真源。小程序从进入接口返回的 Schema 渲染，不自行维护另一组选项。

固定版本号：`schemaVersion = 1`。

### 3.1 年龄区间

字段：`ageRange`，单选、必填。

| code | 展示文案 |
|---|---|
| `under_18` | 18岁以下 |
| `age_18_24` | 18-24 |
| `age_25_34` | 25-34 |
| `age_35_44` | 35-44 |
| `age_45_plus` | 45岁及以上 |

### 3.2 语言文化地区

字段：`cultureRegion`，单选、必填。

| code | 展示文案 |
|---|---|
| `guangzhou` | 广州 |
| `foshan` | 佛山 |
| `jiangmen` | 江门 |
| `hong_kong` | 香港 |
| `macao` | 澳门 |
| `zhuhai` | 珠海 |
| `shunde` | 顺德 |
| `overseas_cantonese` | 海外粤语文化圈 |

该字段表达文化熟悉度，不表达籍贯、户籍或精确位置。

### 3.3 兴趣类型

字段：`interestTypes`，多选、选填。空数组合法。

| code | 展示文案 |
|---|---|
| `language_usage` | 用语 |
| `story` | 故事 |
| `poetry` | 诗歌 |
| `place_name_explanation` | 地名解说 |
| `proverb` | 俗语 |
| `natural_conversation` | 自然对话 |
| `cantonese_film_tv` | 粤语影视剧 |
| `cantonese_dubbed_animation` | 粤语配音动画片 |
| `other` | 其他 |

选择“其他”不展示自由文本输入，避免引入未经定义的原始文本和敏感信息。

### 3.4 Schema 变更规则

- V1 问卷档案创建后不可编辑。
- 文案微调但含义不变时不提升版本。
- 增删选项、改变必填性或改变字段含义时必须提升 `schemaVersion`。
- V1 已完成用户不会因新版本自动重新填写；是否要求重填必须作为后续独立需求评审。

## 4. 用户档案与联系方式

### 4.1 问卷档案

- 每个有效用户最多一份问卷档案。
- 档案与 `User.id` 绑定，不按活动重复保存。
- 保存首次完成时间和首次进入活动，用于数据归因。
- 小程序端不提供答案查询、修改或删除接口。
- 后台默认聚合展示，不返回用户答案明细。
- V1 不设置自动过期时间，永久保留。
- 法律合规要求、账号删除流程或安全事件处置可以覆盖永久保留规则。

### 4.2 手机号

- 手机号唯一真源为现有 `User.phoneNumber`，问卷表不重复保存手机号。
- 已绑定手机号视为已完成短信验证，问卷流程只返回脱敏值，不重复发送验证码。
- `User.phoneNumber = null` 时必须发送并校验短信验证码后才能完成参赛登记。
- 问卷流程不支持更换已绑定手机号。
- 手机号被其他账号占用时复用现有账号合并能力，先返回 `MERGE_REQUIRED`；只有用户明确确认后才能合并。
- V1 不主动判断手机号“失效”。只有字段为空才视为联系方式缺失。

## 5. 触发与状态判定

用户必须先完成小程序登录。未登录点击“我要投稿”时先进入登录流程，登录成功后重新发起问卷进入请求。

服务端按以下顺序判定：

```text
用户点击“我要投稿”
  -> 活动不存在或不可投稿：拒绝
  -> 无问卷档案：full_questionnaire
  -> 有问卷档案但 User.phoneNumber 为空：phone_only
  -> 问卷档案和手机号均完整：reused
```

| `flowType` | 前端动作 | 说明 |
|---|---|---|
| `full_questionnaire` | 展示 Step 1，再展示问卷与联系方式 | 首次完整登记 |
| `phone_only` | 只展示联系方式补充弹窗 | 兼容历史数据或异常恢复；新提交应保持问卷和绑定原子性 |
| `reused` | 直接进入投稿页 | 不展示完整问卷 |

`registrationType` 的后台筛选映射：

- `first_time`：`full_questionnaire` 与 `phone_only`。
- `reused`：`reused`。

## 6. 提交流程与原子性

### 6.1 首次完整登记

```text
点击“我要投稿”
  -> 记录 click_submit_cta
  -> 展示用途说明
  -> 记录 open_questionnaire
  -> 用户继续并填写问卷
  -> 已有手机号：直接提交
  -> 缺少手机号：发送验证码并校验
  -> 一个事务内绑定手机号、创建问卷档案、记录 complete_questionnaire
  -> 展示成功态
  -> 服务端确认进入投稿页并记录 enter_submission_page
```

手机号绑定或档案创建任一步失败时，不得留下“已完成登记”的半成品状态。

### 6.2 联系方式恢复

`phone_only` 不允许重新提交或覆盖问卷答案，只允许验证并绑定手机号。绑定成功后档案转为可复用状态。

### 6.3 资料复用

`reused` 路径不弹问卷，服务端仍创建本次参赛旅程并记录进入投稿页事件，以便按活动归因。

### 6.4 投稿门禁

- 活动投稿必须携带有效的 `questionnaireJourneyId`。
- 旅程必须属于当前用户和当前活动，且已记录 `enter_submission_page`。
- 旅程有效期为 24 小时。
- 普通非活动投稿保持现有行为，不要求问卷旅程。
- 成功创建投稿时，服务端在同一事务内记录 `submit_submission_success`，不能依赖前端补报。

## 7. 事件与归因口径

### 7.1 标准事件名

| 事件 | 记录方 | 含义 |
|---|---|---|
| `click_submit_cta` | 进入接口服务端 | 收到用户对某活动的投稿意图 |
| `open_questionnaire` | 小程序上报 | 问卷或手机号弹窗首次渲染成功 |
| `continue_questionnaire` | 小程序上报 | 用户从用途说明进入填写页 |
| `cancel_questionnaire` | 小程序上报 | 用户主动取消本次登记 |
| `complete_questionnaire` | 提交接口服务端 | 问卷档案与联系方式均已完整 |
| `enter_submission_page` | 进入投稿接口服务端 | 服务端校验通过并允许进入投稿页 |
| `submit_submission_success` | 投稿创建接口服务端 | 投稿记录创建成功 |

旧 PRD 中的 `join_click`、`questionnaire_popup_show`、`questionnaire_submit_success`、`post_entry_success` 不再作为实现名称。

### 7.2 幂等与去重

- 每次进入流程生成一个服务端 `journeyId`。
- 客户端事件必须携带 UUID `clientEventId`，服务端做唯一约束。
- 原始事件全部保留；看板 UV 按“用户 + 活动 + 自然日 + 事件”去重。
- 一次投稿只归因给同一用户、同一活动最近一次有效 `enter_submission_page`，有效期 24 小时。

### 7.3 两条漏斗

首次登记漏斗：

```text
点击我要投稿 -> 打开问卷 -> 完成问卷 -> 进入投稿页 -> 成功提交作品
```

资料复用路径：

```text
点击我要投稿 -> 复用资料进入投稿页 -> 成功提交作品
```

两条路径分别计算，不将跳过问卷步骤的复用用户塞入首次登记漏斗。

## 8. 看板指标决策

首页仅显示三张 KPI：

1. 已完成参赛前登记：`profile.completedAt` 落入筛选范围的去重用户数。
2. 登记后投稿率：带有效问卷档案进入投稿页的去重用户中，24 小时内在同一活动成功投稿的比例；首次和复用用户均可进入此指标。
3. 资料复用率：`reused` 路径进入投稿页 UV ÷ 所有有效档案进入投稿页 UV。

问卷完成率只出现在首次登记漏斗和活动对比详情，不作为首页 KPI。

时间筛选基准：

- 完成登记人数：`profile.completedAt`。
- 首次登记漏斗：起点 `click_submit_cta.occurredAt`。
- 资料复用路径：起点 `click_submit_cta.occurredAt`。
- 登记后投稿率：`enter_submission_page.occurredAt` 形成 cohort，向后观察 24 小时。
- 自定义时间最大跨度为 365 天。

最近 24 小时 cohort 可能尚未完成归因，后台需标记“数据仍在更新”。

## 9. 活动状态、权限与隐私

### 9.1 活动对比状态

- 进行中：`status = published`，已到开始时间，且未到结束时间或无结束时间。
- 已结束：已超过结束时间，或 `status = archived`。
- `draft` 与 `offline` 默认不进入进行中/已结束 Top 5。

### 9.2 活动授权

- 系统管理员和超级管理员默认可访问全部活动。
- 活动运营只能访问管理员显式分配的活动。
- 无授权记录默认拒绝。
- 查看聚合看板与导出聚合报表分别授权。
- V1 为单租户，不接受或存储 `tenantId` 请求参数。

### 9.3 隐私与导出

- 默认页面、图表、下钻和导出不得返回手机号、姓名、UID、精确地址或原始自由文本。
- 分组样本数小于 10 时不得返回精确转化率；显示“样本量不足”或合并为“其他”。
- 导出仅支持聚合 CSV/XLSX，异步生成，下载链接 24 小时失效。
- 查看用户级详情、访问联系方式、授权活动和导出必须写入专用审计日志。
- 问卷洞察 V1 不提供用户级问卷答案入口。

## 10. 验收基线

- 匿名用户不能创建问卷旅程。
- 非用户主动点击不得触发问卷。
- 年龄、地区缺失时提交失败；兴趣类型空数组提交成功。
- 绑定手机号用户不重复验证；未绑定用户必须通过短信验证。
- 问卷档案只能创建一次，不能由小程序读取、覆盖或删除。
- 首次登记和复用路径分别统计且不会形成倒挂漏斗。
- 活动投稿绕过问卷旅程时被拒绝。
- 首页固定三张 KPI。
- 活动标签和兴趣类型在字段、图表与导出中严格分离。
- 未授权运营人员不能查询或导出活动数据。
- 小样本和敏感字段保护在接口层生效，不能只依赖前端隐藏。
