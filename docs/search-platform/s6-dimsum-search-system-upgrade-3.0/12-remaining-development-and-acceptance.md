本记录区分代码已实现、尚待开发、跨团队联调和明确延后范围。没有重跑生产验收，也未核验 Agent/AW 外部仓库；不能把本仓库未实现等同于合作方完全没有实现。

## 1. 当前判断

搜索核心和多媒体基础已有实现。距离本期完整交付，主要还需完成分类建议到正式回写、AW 标注联调、统一分享权限和上下文，以及相关展示、埋点和验收。

不宜给出“完成百分比”：外部契约、公开分享政策和验收范围尚有未冻结项，现有文档还混有已延后方案。

### F 的具体证据

`main/lib/search/entry-query.ts` 的 fetchEntryIdentitiesByUniqueIds 从 get_entry_identities 选择字段时不包含两个新字段；随后 buildEntryIdentity 对缺失值分别回退为 unclassified 和 [text]。因此详情 DTO 存在信息丢失，即使媒体 URL 仍能从 JSON 解析出来。

### 新表不是前置必需项

正式结果继续使用 corpus_category。候选/回写状态优先复用 Agent 任务历史，只有其不足以支持可靠写回时再评审 corpus_category_review_state。没有依据要求重新创建一整套 Agent/审核/媒体/分享表。

## 4. 数据待办与范围边界

1. **253 条混合属性数据**：历史记录保留 unclassified。需要交付待处理清单并保留产品决策；目录未发现最终导出成品，是否在外部交付需核验。可以继续留在默认搜索中，不应为“清零”而自动猜测。
2. **新增数据属性维护**：媒体有 trigger，内容属性不会因新增正文自动确定。需要结合既有写入方落实属性填写/确认；不能将设计规则“正式整理前有属性”误当成所有入口已经强制执行。
3. **存量 source=rule**：定义迁移/展示口径，不能批量标成人工审核通过。
4. **征集投稿转正式语料**：当前审计指出缺 ingestion 闭环，但精简范围明确属于独立需求，不计入当前 Search 3.0 必做开发。

## 5. 仍需执行的联调与验收

### 数据更新维护交接

补充确认“语料变更 → 数据侧重算 embedding → 近邻更新 → 搜索消费”的责任和完成信号。旧契约将语料向量维护归后端数据侧，但外部 Agent 是否自动触发尚未核验；本仓库近邻脚本当前按手册由开发者本地手动执行。

需明确字段变化触发范围、失效向量替换、updated_at、失败重试，以及近邻执行人和维护频率。少量向量变更后增量更新，周期性全量修正旧词条对新目标的近邻关系。先落实交接，不默认新增自动调度或任务表。

具体机制与命令见 [embedding 与离线近邻更新职责](../entry-identity-search/semantic-search-optimization/embedding-and-neighbor-maintenance.md)。

### 功能与性能验收

- Agent → 平台 → AW → 平台正式分类 → Search 展示的端到端测试。
- 重复回调、两人并发、过期分类树、证据不存在、Agent 完成后本地写回失败及重试。
- 默认搜索兼容、显式属性三段隔离、缓存和 fallback 不跨属性、媒体筛选与推荐稳定性。
- 搜索结果与详情字段一致；分类未确认时不泄露候选和内部依据。
- AW 分享权限、二维码落点、固定 UUID、失败降级及贡献者字段处理。
- 已有音视频/图片/3D UI 的真实设备及中英文验收，列表不预载视频流。
- 冷热缓存固定查询集的 p50/p95/p99、fallback 和错误率；确认最终 SLO 后留档。08 文档中的性能门槛目前仍标为待确认，不能把历史单次冒烟耗时当作已通过 p95 验收。

- README/11 部分描述仍把媒体 UI 视作待实施/独立分支，但当前代码已合并。
