# 语料集属性与活动专属语料集

日期：2026-09-13。状态：本地实现及验证完成；经用户明确授权，生产数据库已按 pull → 库内回填 → push → pull 核验完成迁移，旧条目属性字段已删除。应用尚未部署，Git 尚未提交。

## 1. 最新业务规则（覆盖旧条目级属性方案）

- 内容属性属于语料集 `cantonese_categories.content_attribute`；正式语料通过 `category -> cantonese_categories.name` 继承。
- 配置值为 oral / cultural_knowledge。unclassified 只用于存量待配置，不允许创建新活动时选择。
- 单条语料不再维护 content_attribute；media_types 仍属于单条语料，保留现有派生 trigger。
- 后台原 `/admin/categories` 更名为“语料集管理”，复用原有表和入口。
- 别名复用 nickname，可修改别名与说明，内部 name 不可变；修改属性影响整个语料集，保存时记录原值、新值和操作人。
- 一活动一专属语料集，不提供多活动共用或活动改绑语料集入口。
- 创建活动时必选属性，活动与语料集在同一事务内创建。显示别名默认等于活动标题，之后独立维护；活动改名不改内部标识。
- 新活动语料集初始不公开、也不主动加入来源选择器的全局列表。活动发布不等于正式语料发布，沿用现有公开控制。
- 已有活动补建空语料集，属性待配置；不会把历史投稿自动变成正式语料。未来入库应从 activity.dataset_name 获得归属。

## 2. 数据结构

| 结构 | 变更 |
| --- | --- |
| cantonese_categories | 新增 content_attribute、B-tree 索引和合法值检查；复用 nickname 作为别名 |
| corpus_collection_activities.dataset_name | 独立外键指向语料集 name；唯一约束保证一对一；最终 NOT NULL |
| corpus_collection_activities.creation_key / creation_hash | 创建请求幂等键与规范化请求摘要；相同请求重试复用结果，不同内容复用同键返回 409 |
| cantonese_corpus_all.content_attribute | 最终删除字段及依附索引/约束，保留媒体字段 |

外键采用 RESTRICT，不能误删已关联的语料集。活动删除不级联删除语料集。无需重建正文、向量或离线近邻。

Prisma 先按真实库 pull 结果对齐：发现 ignored 模型 app_lib_h5_survey 的旧 wechat_id 已在线上变为 phone/event_id，本地保留该真实结构对齐，不对线上进行反向覆盖。

## 3. API 和页面

- `GET/PATCH /api/admin/categories`：增加集级属性、活动关联、别名/说明修改；管理员鉴权，行锁和审计写入同事务。
- `POST /api/admin/corpus-collection/activities`：新增必填 contentAttribute、creationKey（UUID）。后台页面自动生成 creationKey；相同键及相同请求返回已有结果，不重复建集。首次 201，重试 200，冲突 409。
- 创建活动失败时语料集回滚；事务锁串行化同一创建键的并发请求。
- 活动列表、详情、状态操作返回 dataset 上下文；活动编辑接口拒绝从活动端修改属性或重新绑定语料集，统一到语料集管理维护。
- 搜索精准、语义、fallback 路径均通过所属语料集过滤；DTO 的 contentAttribute 保留兼容字段名，但值是继承值。
- UUID 详情补齐集级属性和媒体字段，避免旧详情默认返回 unclassified/text。
- 修改别名或属性后后台刷新关联查询并触发详情路径失效；Search 响应改为 no-store，避免 CDN 继续返回旧集级属性；query embedding 缓存和离线邻居不受影响。客户端查询在重新挂载/聚焦时重新验证，已打开的其他设备页面不承诺主动推送更新。

缓存调整会减少 Search CDN 命中，发布验收应关注数据库负载与分段延迟；后续可增加按语料集版本的缓存策略，但不能重新引入无法失效的旧属性缓存。

## 4. 存量迁移与发布顺序

以下为原先建议的分阶段发布方案。本次用户明确要求“先 pull 再 push，原来的语料属性字段可以直接删”，因此实际执行已提前完成删除，见第 7 节；不得再按下文的迁移前状态判断当前数据库。

脚本位于 [main/scripts/dataset-attributes](../../../main/scripts/dataset-attributes)。普通 Prisma schema 真源流程仍为 pull → diff 审查 → 变更；本次涉及跨表搬迁和兼容旧应用，提供显式分阶段 SQL，不能直接对最终 schema 执行带删除的 db push。

1. 发布前再次 pull 并审查真实 diff，确认没有新增结构变化；备份旧属性与来源映射。
2. 执行 `01-expand-and-backfill.sql`：新增集级字段、活动关联与幂等字段。只有来源内旧属性一致且为 oral/cultural 的语料集自动回填；冲突或未知保留待配置，已有配置不覆盖。
3. 同一脚本为旧活动补建专属语料集。名称由 activity display_uuid 派生，不按标题猜测或复用语料集；冲突时事务失败，避免误关联。脚本可重复执行。
4. 部署本次应用，确认后台别名/属性编辑、创建活动、默认/显式搜索及详情均正常；旧应用写入者必须退出。
5. 再跑 expand/backfill，补齐滚动发布期间旧应用可能创建的未关联活动；确认没有遗漏和待处理冲突。
6. 确认不再回滚到读取条目属性的旧代码后，执行 `02-contract.sql`：设置活动关联 NOT NULL，删除旧条目属性。脚本不使用 CASCADE，未知依赖会阻止删除。
7. pull 核对最终结构，保留验收记录。

删除旧字段之前可回滚旧应用；删除之后不能直接回滚到依赖旧字段的旧版本。待配置数据可以由管理员按语料集补选，不因本次迁移擅自改变默认搜索的公开范围。

原本地测试使用隔离数据库和模拟 UI 数据；后续生产迁移与只读验证记录见第 7 节。尚未提交/发布本次应用改动。
