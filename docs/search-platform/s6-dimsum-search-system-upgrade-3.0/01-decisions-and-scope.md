# 01 · 决策基线、范围与职责

状态：待确认

## 一、核心术语

### 1.1 默认搜索与可选属性过滤

默认搜索不传 `contentAttribute`，沿用现有全库搜索和排序。精准搜索匹配到哪条内容就展示哪条，不先要求用户选择口语语料或文化知识。

当调用方明确传入 `oral` 后，一级精准、二级相关、三级推荐返回的每条内容都必须满足：

```text
entry.content_attribute = oral
```

传入 `cultural_knowledge` 时同理。显式过滤后的当前范围结果不足时返回空结果，不允许服务端用另一属性内容补足数量。

因此，“不得混排”只适用于显式属性过滤模式；默认未过滤模式允许不同属性内容按现有召回和排序共同出现。

媒体类型不是内容属性。例如视频既可能是口语访谈，也可能是文化纪录片；不能根据 `video` 自动判断为 `oral`。

### 1.2 三段召回统一过滤

三段召回可以使用不同的排序算法。本期不改变现有 Search 的基础检索范围；内容属性只在请求明确提供时成为三段共同硬过滤：

```text
[如果请求提供 contentAttribute]
content_attribute = 请求值
```

其中：

- primary 在文本匹配之前或同一 SQL 中过滤；
- related 在向量、标签、分类和邻居候选产生后再次过滤；
- recommended 在推荐候选产生后再次过滤；
- 缓存键必须区分 `contentAttribute=none`、`oral` 和 `cultural_knowledge`。

## 二、已确认范围

### 本期包含

- 存量与新增内容的属性标记。
- 复用现有词条身份、来源、分类、标签、贡献者和分享链路。
- 新增 `content_attribute` 和 `media_types` 两个本期搜索字段。
- Agent 二级分类预标注和路由。
- AW 分类确认、分类抽检、暂不分类和处理记录。
- 现有 Search API 的可选内容属性过滤能力和三层结果。
- 方案 B 媒体筛选。
- 视频关键帧、时长、播放面板、时间码转写和失败降级。
- Fynn 公开权限接口与 AW 分享卡片服务对接。
- SEO 词条详情和规定埋点。

### 本期不包含

- 视频批量切片生产链路。
- 图片 OCR、图内对象坐标和对象知识关联。
- 个性化推荐。
- 分类/标签聚合 SEO 页深化。
- 分享模板运营后台。
- Search Web/App 的口语语料/文化知识属性选择器交互。

## 三、已确认的产品决策

### D-01 媒体筛选

采用方案 B：`mediaType` 只影响二级相关结果。

- primary 永远展示最佳精准内容。
- related 后端按 text/audio/video/image/model3d 筛选；model3d 前端入口待产品确认。
- recommended 不受媒体筛选影响。
- 媒体筛选切换时不改变搜索词或可选内容属性参数。
- 本期 URL 保存 `mediaType`；后续属性选择器上线时再保存 `contentAttribute`。

### D-02 空状态与属性交互分期

- 本期默认未过滤搜索：三段均为空时显示普通全库空状态，不显示属性切换入口。
- 显式属性过滤模式：当前属性三段均无结果时返回范围空状态信号。
- primary 为空但 related/recommended 有值时正常展示后两段。
- related 经媒体过滤后为空：只显示相关区空状态，primary/recommended 保持显示。
- 另一属性是否有结果可由 API 返回可用性信号；前端属性选择器和切换入口后续实现。

### D-03 训练许可与公开许可解耦（业务语义已确认、字段延后）

业务语义保持：禁训不自动禁止公开搜索或分享。但当前系统没有训练集导出治理链路，本期不新增 `train_permission/rights_status/review_status`。

Production 已存在 `lifecycle_stage` 和来源 `is_public`，但当前 Search 没有把二者统一组合为查询条件，PRD 也没有明确要求本期新增该门槛。因此 S6 默认搜索不增加这两个条件。它们是否应共同定义公开范围，作为待决策项保留；训练许可字段在出现明确写入方和训练数据消费方后单独实施。

### D-04 分享职责

- AW：卡片视觉、模板、渲染、二维码和端侧分享体验。
- Fynn：词条真实数据、公开权限、固定落地链接、服务鉴权和审计事件接收。
- Search Web/App：调用 AW 分享入口，不自行复制一套权限规则。

### D-05 版本

本项目统一称为 S6 / Search 3.0。旧文件中的 S7、v6、2026-08-09 等标识只代表历史 Demo 版本，不代表当前接口版本。

### D-06 状态与来源公开性的检索规则（待决策）

- `lifecycle_stage` 更接近数据加工阶段，`is_public` 是来源级属性，二者都不是已确认的条目级发布状态。
- Production 交叉分布为：draft/非公开 19,691、draft/公开 131、normalized/非公开 11、normalized/公开 31,161。
- 若直接启用 `normalized + is_public=true`，会改变现有默认搜索范围；在未完成影子查询和产品确认前不得作为 S6 硬过滤上线。
- 本期结论：记录观察、保留后续决策；默认搜索兼容现状，显式属性请求只额外增加 `content_attribute` 条件。

### D-07 Schema 与线上验证流程

- Production 数据库是当前 schema 真源；凡涉及 schema 变更，必须先执行 `prisma db pull`，审查拉取后的 diff，再编辑目标字段并执行 `prisma db push`。
- 禁止跳过 pull 直接用本地旧 schema 覆盖线上结构。
- `content_attribute`、`media_types` 和可选过滤均为向后兼容增量，不改变旧 Search 默认行为，因此不为它们增加功能开关。
- 完成结构同步、回填核对和接口测试后，允许直接在 Production 使用测试请求验证；测试请求不得改变普通用户的默认搜索语义。
- Prisma 无法表达的函数、trigger 或检查约束必须作为补充 SQL 单独评审和执行，不能假设 `db push` 会创建这些对象。

## 五、已确认补充规则

1. 首批存量语料无法可靠判定内容属性时，先导出待处理清单，不自动猜测、不立即批量创建人工任务。
2. `pending_sample` 不公开显示二级分类，可用于普通相关/推荐召回；满足其他公开条件时允许分享，但卡片隐藏该分类。
3. 分享卡片在二级分类 `pending_review` 时完全禁止。
4. 前端属性选择器后续再做；本期先完成数据库标记、导出和现有 Search API 的可选过滤能力。
