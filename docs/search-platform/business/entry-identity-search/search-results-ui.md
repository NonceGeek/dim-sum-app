# 搜索结果 UI 展示建议

## 一、UI 目标

PRD 中的搜索结果不是普通列表，而是一个从“精准命中”到“继续发现”的渐进式信息架构：

```text
一级精准结果：让用户确认“这就是我要找的词条”
二级相似结果：让用户继续看相近词条
三级推荐结果：让用户探索更宽泛内容
```

因此 UI 不建议把三类结果混排成同一种卡片。应该通过层级、密度和信息量区分：

- 一级结果大卡片，信息完整。
- 二级结果中卡片，强调相似原因。
- 三级结果小卡片或横向列表，强调轻量探索。

---

## 二、整体页面结构

### 2.1 桌面端

建议结构：

```text
顶部搜索栏
  -> 搜索输入、dataset 选择、语言/地区筛选

结果摘要
  -> About N results
  -> 当前命中 dataset / 分类 / 标签提示

一级精准结果
  -> 1 个主结果优先展示
  -> 只展示 1 个最佳命中

二级相似结果
  -> 2-4 列卡片网格
  -> 一次展示 3 个

三级推荐结果
  -> 横向小卡 / 标签组 / 热门词
  -> 一次展示 4 个
```

桌面端一级结果建议使用左右结构：

```text
左侧：词条内容、粤拼、释义、音频/图片
右侧：身份信息、分类、标签、Unique ID、分享操作
```

### 2.2 移动端

移动端不适合左右结构，建议纵向堆叠：

```text
顶部固定搜索栏
一级精准结果大卡
二级相似结果双列或单列
三级推荐结果标签流
```

一级结果的身份信息可以折叠：

```text
默认展示：词条、粤拼、释义、主要标签、分享按钮
展开展示：Unique ID、来源、一级/二级分类、贡献者、更多标签
```

---

## 三、一级精准结果设计

### 3.1 展示内容

一级结果需要承载完整 `entryIdentity`：

| 区域 | 字段 |
|------|------|
| 主标题 | `entryName` / `data` |
| 发音 | 粤拼 |
| 释义 | `meaning` |
| 媒体 | 音频优先，其次图片/视频封面 |
| 身份 | `unique_id`、来源语料库、贡献者 |
| 分类 | `content_categories` 聚合出的一级/二级身份分类 |
| 标签 | precise / related / recommended |
| 操作 | 分享卡片、复制链接、复制 Unique ID |

### 3.2 视觉层级

建议：

- 词条标题最大。
- 粤拼紧跟标题下方。
- 释义用正文，不要被标签和 ID 挤压。
- Unique ID 展示为低优先级信息，但复制按钮要清晰。
- 标签按类型分组，不要把所有标签混成同一排。

### 3.3 操作按钮

一级结果建议保留三个操作：

| 操作 | 说明 |
|------|------|
| 分享卡片 | 打开卡片预览弹窗或移动端底部弹层 |
| 复制链接 | 复制 SEO 或卡片链接 |
| 复制 ID | 复制 `unique_id`，便于运营和排查 |

分享卡片是主操作，复制链接是次操作，复制 ID 是工具操作。

---

## 四、二级相似结果设计

### 4.1 展示内容

二级结果不需要展示完整身份信息，重点是让用户知道“为什么它相似”。

建议字段：

| 字段 | 说明 |
|------|------|
| 词条名 | `entryName` |
| 简短释义 | 最多 1-2 行 |
| 相似原因 | 例如同标签、同二级分类、语义相似 |
| 主要标签 | 2-3 个 |
| 来源 | 语料库 nickname |

### 4.2 卡片形态

桌面端：

```text
2-4 列网格卡片
```

移动端：

```text
双列卡片或单列紧凑卡片
```

如果内容很长，移动端优先单列，避免卡片挤压导致释义不可读。

### 4.3 相似原因展示

二级结果建议展示一个简短 reason：

```text
同标签：冲突
同分类：日常口语
语义相似
```

这能帮助用户理解推荐不是随机出现，也方便后续调试排序质量。

---

## 五、三级推荐结果设计

### 5.1 展示目标

三级结果是探索区，不应抢一级和二级结果的注意力。

适合展示：

- 推荐标签。
- 相关热门词。
- 同分类高热词条。
- 运营配置词。

### 5.2 展示形态

建议使用更轻的 UI：

```text
标签胶囊 + 小词条卡
```

例如：

```text
推荐探索
[日常口语] [俗语] [冲突表达] [文化视频]

好行夹唔送   俾面   唔该晒   冇所谓
```

三级结果可点击后触发新搜索，或进入对应标签/分类页。

---

## 六、分享卡片弹窗

### 6.1 Web 端

点击“分享卡片”后建议打开居中弹窗：

```text
标题：分享卡片预览
主体：卡片预览图
底部操作：下载图片 / 复制链接 / 发布到社群
```

弹窗内卡片字段：

- Logo。
- 词条名。
- 粤拼。
- 一句话释义。
- 来源语料库。
- 分类。
- 标签。
- Unique ID。

### 6.2 移动端

移动端使用底部弹层：

```text
卡片预览
保存图片
复制链接
系统分享
```

卡片高度需要控制，避免用户需要滚动很久才能看到操作按钮。

---

## 七、分页与加载交互

### 7.1 总体原则

产品已确认：一级精准结果只有一个，二级相似结果和三级推荐结果都采用“换一批”刷新，不做追加加载，也不使用传统分页器：

```text
1 2 3 4 下一页
```

原因是本需求的搜索页不是单一结果列表，而是三个不同目标的结果区：

```text
一级精准结果：答案区
二级相似结果：相关内容区
三级推荐结果：探索区
```

如果使用全局分页，用户会不清楚翻页后到底是在翻精准结果、相似结果还是推荐结果。最终交互收敛为：

- 一级精准结果只展示 1 个最佳答案。
- 二级相似结果展示一批，点击“换一批相似结果”直接替换当前二级区。
- 三级推荐结果展示一批，点击“换一批推荐”直接替换当前三级区。
- 不做全局分页，也不做 section 内追加加载。

### 7.2 首次搜索交互

用户输入关键词并搜索后，页面首屏建议展示：

```text
搜索框
About 1000 results

一级精准结果
[大卡片：相骂冇好口]
  粤拼 / 释义 / 来源 / 标签 / 分享按钮

二级相似结果
[相似词条卡] [相似词条卡] [相似词条卡]
换一批相似结果

三级推荐探索
[日常口语] [冲突表达] [俗语] [文化视频]
[推荐小词条] [推荐小词条] [推荐小词条] [推荐小词条]
换一批推荐
```

一级精准结果只展示 1 个最佳命中，二级相似结果每批展示 3 个，三级推荐每批展示 4 个。

### 7.3 二级结果换一批

用户点击“换一批相似结果”时，只刷新二级结果，不刷新整个页面。

交互规则：

- 保留一级精准结果。
- 替换当前二级结果。
- 保持三级推荐不变。
- 请求下一批 similar。
- 如果没有可替换结果，按钮置灰或隐藏。

桌面端替换当前网格卡片；移动端替换当前相似结果列表。

### 7.4 三级推荐换一批

用户点击“换一批推荐”时，只刷新三级推荐，不刷新整个页面。

交互规则：

- 保留一级精准结果。
- 保留当前二级相似结果。
- 替换当前三级推荐。
- 请求下一批 recommended。
- 如果推荐池不足，可以在当前批次内打乱顺序或隐藏按钮。

### 7.5 移动端交互

移动端建议：

```text
搜索框
一级精准结果大卡
查看更多身份信息

相似结果
[卡片]
[卡片]
[卡片]
换一批

推荐探索
[标签] [标签] [标签]
[小词条] [小词条]
换一批
```

移动端不要出现传统分页器，也不要做无限下拉。每次“换一批”只替换当前 section，避免页面越来越长。

---

## 八、空状态和降级状态

### 8.1 无一级精准结果

如果没有强命中：

```text
不展示“一级精准结果”标题
直接展示“相关结果”
```

避免用户看到一个空 section。

### 8.2 无二级相似结果

如果没有相似结果：

```text
隐藏二级 section
展示三级推荐或热门搜索
```

### 8.3 向量服务不可用

如果向量召回失败：

```text
一级结果仍正常展示
二级结果退回标签/分类召回
三级结果退回热门词/运营配置
```

UI 不需要向用户暴露“向量服务失败”，只需要保证结果可用。

---

## 九、推荐的响应字段

为了支持 UI 解释召回原因，建议每条结果增加：

```json
{
  "entryIdentity": {},
  "match": {
    "section": "similar",
    "type": "tag",
    "score": 0.82,
    "reason": "同标签：冲突"
  }
}
```

`reason` 可以直接展示在二级/三级卡片上，也可以只用于调试。

---

## 十、首期落地建议

首期不要一次做太复杂，建议先落：

| 优先级 | 内容 |
|--------|------|
| P0 | 一级精准结果大卡，完整展示身份信息 |
| P0 | 二级相似结果卡片，基于标签/分类召回 |
| P0 | 二级结果和三级结果都支持“换一批” |
| P0 | 分享卡片弹窗，支持复制链接 |
| P1 | 三级推荐标签和热门词 |
| P1 | 相似原因 `reason` 展示 |
| P2 | 向量召回结果融合 |
| P2 | SEO 词条页和标签/分类聚合页 |

这样能先满足 PRD 的可见体验，又不会被向量搜索、推荐权重、SEO 全部绑在一起。
