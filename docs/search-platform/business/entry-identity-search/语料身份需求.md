### 语料分类

两张表：

- `content_categories` = 两级分类树
- `corpus_category` = 语料→分类的归属

- **两级树**：`level=1` 一级（`parent_id` 空）、`level=2` 二级（`parent_id` 指一级）；**语料只挂二级**。
- **单一归属**：一条语料**最多一个**分类（`corpus_category` 主键 = `corpus_id`）；未归类则**没有行**。
- `item_count` 是离线刷的缓存数，非实时。
- 要软删除可以用 status=deprecated

**建表 DDL**

```sql
-- 分类树（两级，单表自引用）
create table content_categories
(
    id          bigint generated always as identity primary key,
    slug        text        not null unique,                  -- SEO URL 用：'idiom' / 'idiom-3char'
    name        text        not null,                         -- 展示名：'词语习语'
    parent_id   bigint references content_categories (id) on delete restrict,
    level       smallint    not null check (level in (1, 2)), -- 1=一级 2=二级
    sort_order  int         not null default 0,
    status      text        not null default 'active' check (status in ('active', 'hidden', 'deprecated')),
    description text,
    item_count  int         not null default 0,               -- 归属语料数缓存，离线定时刷新
    created_at  timestamptz not null default now(),
    updated_at  timestamptz not null default now(),
    constraint cc_level_parent check                          -- 一级无父、二级必有父
        ((level = 1 and parent_id is null) or (level = 2 and parent_id is not null))
);

-- 语料归属（单一归属：PK = corpus_id；未归类则无行），建单独表的原因是：未来大概要记一些分类相关的 meta 信息，比如谁设置的分类
create table corpus_category
(
    corpus_id   bigint primary key references cantonese_corpus_all (id) on delete cascade,
    category_id bigint      not null references content_categories (id) on delete restrict,
    source      text        not null default 'rule' check (source in ('rule', 'manual')),
    assigned_by text references "User" (id),
    assigned_at timestamptz not null default now()
);

```

### 语料标签

三张表：

- `tags` = 标签词表（每个标签属一个 facet 维度）
- `corpus_tags` = 语料↔标签多对多；
- `tag_related` = 离线预算好的相关标签（分 method 存 cooc/semantic/manual 三种原始信号）。

- tag 有维度的概念，对应 facet 列。运营新增 tag 时，如果不想选维度可以默认落进 other 里，后面再手动修改。
- tag 有释义这一列：gloss，用来在向量化的时候作为输入，解决标签一般都很短很容易语义不准确的问题。可以在运营新增的时候填进去。
- 要软删除可以用 status=deprecated
- 因为 tag 的变动不会很频繁，提供了一个预先算好的相关标签表 tag_related，可以直接用也可以用其他方式，取决于推荐逻辑本身。表提供了三个不同的相关信号，各有优劣，见下表。
- 除了利用 tag_related 做标签推荐，也可以使用 tags.facet （相当于标签的自己的分类作为推荐的一个维度参考）

| method 列        | 含义                                          |
|-----------------|---------------------------------------------|
| **共现** cooc     | `corpus_tags` 统计：常打在同一条语料上的标签，标签打的不够多的时候不太准 |
| **语义** semantic | 标签释义向量化之后的后 cosine 最近邻                      |
| **人工** manual   | 运营手动设置的相关性，目前没数据，如果要在后台加类似功能可以放入这张表         |

DDL 如下：

```sql
-- 标签词表（一个 tag 一行）
create table tags
(
    id           bigint generated always as identity primary key,
    slug         text        not null unique,         -- SEO URL，连字符：'scene-dining'
    name         text        not null,                -- 展示名：'就餐场景'
    facet        text        not null default 'other' -- 标签的维护，类似标签的小分类，也可以用来作为推荐维度参考，运营不填落 'other'
        check (facet in ('kind', 'media', 'language', 'source',
                         'scene', 'topic', 'region', 'dialect', 'other')),
    sort_order   int         not null default 0,      -- 展示排序（吸收场景数字前缀）
    status       text        not null default 'active'
        check (status in ('active', 'deprecated')),   -- 软删，不破历史关联
    gloss        text,                                -- 标签释义；向量化(embedding)的输入——embed 释义而非字面量，喂语义「相关标签」(§6)
    embedding    vector(1024),                        -- gloss 的语义向量（qwen3-vl-embedding，1024 维）
    corpus_count int         not null default 0,      -- 关联语料数缓存，离线定时刷新
    created_at   timestamptz not null default now()
);

-- 语料↔标签（多对多）
create table corpus_tags
(
    corpus_id  bigint      not null references cantonese_corpus_all (id) on delete cascade,
    tag_id     bigint      not null references tags (id) on delete restrict,
    source     text        not null default 'import' check (source in ('import', 'manual', 'auto')), -- 运营在后端手动设置的时候可以设置为 manual
    created_by text references "User" (id),                                                          -- 是谁给语料打的标签
    created_at timestamptz not null default now(),
    primary key (corpus_id, tag_id)
);

-- 分 method 存原始相关分（便于以后调权重而不用重算每个信号）
create table public.tag_related
(
    tag_id     bigint not null references public.tags (id) on delete cascade,
    related_id bigint not null references public.tags (id) on delete cascade,
    method     text   not null check (method in ('cooc', 'semantic', 'manual')),
    score      real   not null,
    primary key (tag_id, related_id, method)
);
```

**常用查询**

```sql
-- 1) 某语料的全部标签（按 facet 分组展示）
select t.facet, t.slug, t.name
from corpus_tags ct
         join tags t on t.id = ct.tag_id
where ct.corpus_id = $1
  and t.status = 'active'
order by t.facet, t.sort_order, t.name;

-- 2) 某标签下的语料（标签页反查，分页；$1 传 slug）
select co.*
from cantonese_corpus_all co
         join corpus_tags ct on ct.corpus_id = co.id
         join tags t on t.id = ct.tag_id
where t.slug = $1
order by co.id
limit $2 offset $3;

-- 3) 多 facet 过滤（同时满足 内容类型=word 且 场景=就餐 → 每个条件一个 exists）
select co.*
from cantonese_corpus_all co
where exists (select 1
              from corpus_tags ct
                       join tags t on t.id = ct.tag_id
              where ct.corpus_id = co.id
                and t.slug = 'kind-word')
  and exists (select 1
              from corpus_tags ct
                       join tags t on t.id = ct.tag_id
              where ct.corpus_id = co.id
                and t.slug = 'scene-dining')
order by co.id
limit $1 offset $2;

-- 4) 某标签的相关标签（内链 top-12）：直接读 tag_related，按 method 加权融合三种信号
--    权重只是示例，按推荐逻辑自调；join tags 过滤掉弃用/空页标签
select tr.related_id,
       sum(case tr.method
               when 'manual' then 3.0
               when 'cooc' then 1.0
               when 'semantic' then 0.6 end * tr.score) as score
from tag_related tr
         join tags r on r.id = tr.related_id
where tr.tag_id = $1
  and r.status = 'active'
  and r.corpus_count >= 3
group by tr.related_id
order by score desc
limit 12;

-- 5) 语料页推荐标签：展开该语料各标签的相关集（同样直接读 tag_related），聚合去重、排除它已有的
select tr.related_id,
       sum(case tr.method
               when 'manual' then 3.0
               when 'cooc' then 1.0
               when 'semantic' then 0.6 end * tr.score) as score
from tag_related tr
         join tags r on r.id = tr.related_id
where tr.tag_id in (select tag_id from corpus_tags where corpus_id = $1)
  and tr.related_id not in (select tag_id from corpus_tags where corpus_id = $1)
  and r.status = 'active'
  and r.corpus_count >= 3
group by tr.related_id
order by score desc
limit 12;

-- 6) 给语料打标签（去重 upsert；category 是单归属，tag 是多挂）
insert into corpus_tags (corpus_id, tag_id, source, created_by)
values ($1, $2, 'manual', $3)
on conflict (corpus_id, tag_id) do nothing;
```

### 如何查询一条语料的相似语料

一张表：`corpus_field_embeddings` = 语料的**字段级向量**（一条语料按字段拆成多个向量；qwen3-vl-embedding / 1024 维 / 余弦）。

- **为什么多向量**：词条+释义+例句拼成一个向量会互相稀释（搜例句被词条带偏）。所以按 `field_type` 分别建向量、各建一条**部分
  HNSW**，各检索面只扫自己的子空间。
- **field_type 取值**：`doc`(整条综合) / `sentence`(例句) / `definition`(释义) / `headword`(词条) / `image`·`video`(
  跨模态)。
- **corpus_id 软引用** `cantonese_corpus_all.id`，无硬 FK；要展示字段就 join 回语料表。
- **覆盖率**：查不到向量的语料推荐为空，需兜底（如回退标签共现）。

**建表 DDL**

```sql
create table public.corpus_field_embeddings
(
    id          bigserial primary key,
    corpus_id   bigint       not null,                -- 软引用 cantonese_corpus_all.id
    field_type  text         not null,                -- doc/sentence/definition/headword/image/video
    modality    text         not null default 'text', -- text/image/video
    content_ref text         not null,                -- 实际喂模型的串/媒体 URL，复现+调试
    embedding   vector(1024) not null,                -- qwen3-vl-embedding
    updated_at  timestamptz  not null default now()
);
-- 每个 field_type 一条部分 HNSW(vector_cosine_ops)；另有 (corpus_id) 索引、(corpus_id,field_type,md5(content_ref)) 唯一去重
```

**常用查询**

```sql
-- 相关语料推荐(doc→doc)：取该语料 doc 向量，在 doc 子空间做 KNN，排除自己。$1 = 源 corpus_id
-- 必带 field_type='doc' + LIMIT 才命中 HNSW；算子固定 <=>(余弦，索引是 vector_cosine_ops)
with src as (select embedding
             from public.corpus_field_embeddings
             where corpus_id = $1
               and field_type = 'doc'
             limit 1)
select e.corpus_id,
       1 - (e.embedding <=> src.embedding) as similarity -- 0~1，越大越像
from public.corpus_field_embeddings e,
     src
where e.field_type = 'doc'
  and e.corpus_id <> $1
order by e.embedding <=> src.embedding
limit 12;
-- 用 EXPLAIN 确认走 corpus_field_emb_doc_hnsw；若退化成 Seq Scan，改成「先取向量、再用绑定参数 KNN」两步查（最稳走索引）

-- 按某个面找相似(按例句/按释义)：把上面两处 'doc' 换成 'sentence' / 'definition' 即可
```
